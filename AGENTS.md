- Offline support uses vite-plugin-pwa (generateSW) registered only via src/lib/register-sw.ts, which refuses dev/preview hosts — prevents stale preview caches.
- A/B comparison owns separate folder-aware collections per pane; import appends and single-photo removal never resets the other pane, while generation guards prevent late decoding from crossing panes.
- Composition uses a separate session-retained canvas document and native Canvas blend operations, preview capped to 1400px and full-resolution PNG export; flattened results append to the viewer session so existing save/share/clean paths remain unchanged.
- User development presets are versioned and validated in localStorage, excluding geometry/crop so quick application preserves each photo's framing and works offline on every platform.
- Desktop cache clearing (Electron `loma:clearCache`) may delete only exported-photo temp files and Chromium's volatile network cache; never call clearStorageData on serviceworkers/cachestorage — the offline copy of the app lives there and must survive a clean-up pressed while offline.
- Google Drive direct API lives only in Cloud Hub (browser GIS token, Client ID in localStorage, no server) so it works in web, desktop and static APK; the Drive quick button still copies into the desktop sync folder.

- Android APK loads the published site by default (Capacitor server.url, LOMA_LOCAL=1 for a local-only build) with the bundled static SPA export (LOMA_TARGET=android, dist/client) as errorPath offline fallback; src/lib/live-update.ts reloads on start/resume when entry scripts change, so publishes reach tablets without reinstalling. Intent filters are injected by scripts/android-intents.cjs after cap add/sync since android/ is generated.
- Android intents reach the web app through a JavascriptInterface (`LomaAndroid.takeFiles`) in MainActivity.java, generated by scripts/android-native.cjs because android/ is regenerated; icons come from scripts/android-icons.cjs.
- FTP (camera receiver server + NAS client) lives in electron/ftp.cjs using only Node "net", no npm FTP deps, so electron-builder packaging (files list excludes node_modules extras) never breaks; browsers get a simulator only.
- Android FTP receiver is a plain-Java ServerSocket server inside generated MainActivity (scripts/android-native.cjs); destinations use persisted SAF tree grants or public Pictures through MediaStore. Stream to the destination and a disposable cache copy for the existing shared-files push channel (ftp:true → always appended); acknowledge FTP success only after the destination is committed, never silently fall back when a selected folder is inaccessible.

- External prompt sending uses image-only clipboard (native image URI on Android), with text in prefill links or EXTRA_TEXT; never fall back to clipboard text when a photo copy fails, so pasting cannot lose the photo. The explicit combined-copy command remains separate; no model calls or server dependencies.
- Comparison photo transfers move the same collection item and invalidate both pane load generations; pointer dragging supports touch/stylus separately from mouse HTML drag.

- Dettaglio AI and Super Risoluzione are local adaptive filters (detail-ai.ts, ported from LoMa EDIT), never network inference; Super Risoluzione runs only on export. Brush-mask rasters live in session memory (develop.ts MASKS) referenced by Adjust.mask id/version and are excluded from user presets.
